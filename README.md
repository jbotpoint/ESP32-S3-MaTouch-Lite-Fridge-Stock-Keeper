## Overview
This firmware implements a comprehensive, touch-enabled inventory management system for household groceries within a fridge environment using an ESP32-S3 microcontroller. It tracks item names, categories, quantities, and critically, their spoilage dates. The system provides a full user interface across multiple screens: Dashboard, Meal Planner, Inventory Editing, Wi-Fi Setup, and Recipe Management.

**Feature List:**
*   **Inventory Tracking:** Tracks name, category, quantity, date added, and spoilage date for every item.
*   **Spoilage Warning System:** Provides color-coded UI alerts (Green/Yellow/Red) based on remaining shelf life.
*   **Meal Planning (Calendar):** Allows users to assign specific recipes to calendar dates over a visible month view.
*   **Recipe Management:** Enables creation and editing of meals, listing required ingredients per recipe.
*   **User Interface:** Multi-screen application state machine handling complex navigation between modules.
*   **Connectivity Status:** Integrates Wi-Fi status display with automatic retry mechanisms when connectivity is lost or credentials need refreshing.

## Architecture & Components
The system adheres to modular design principles, delegating specific domain logic and hardware interactions to dedicated classes/modules.

### Core Modules (Managed by Global Instances)
*   **TFT_eSPI tft**: Handles all graphical output to the display. Drawing functions are heavily coupled with screen dimensions (SCREEN_W, SCREEN_H) and button coordinates.
*   **NS2009 touch(...)**: Manages reading raw data from the resistive touchscreen. Touch input is processed by touch.Scan() and abstracted into coordinate handling within handleTouch().
*   **GroceryManager groceryManager**: The core inventory database handler. Responsible for CRUD operations on items, calculating remaining days until spoilage, and triggering spoilage warnings (checkSpoilage).
*   **MealsManager mealsManager**: Manages recipes/meals. Includes logic to track which ingredients are needed per meal and the completion status of a recipe.
*   **CalendarEntry calEntries[] / calSave()**: Implements persistent storage for the Meal Planner using LittleFS (/calendar.bin). Allows assignment of specific meals to dates, handling day deletion and meal name lookup.
*   **NetworkManager networkManager**: Handles all Wi-Fi connectivity states (scanning, connecting, credentials saving). It manages the state machine related to the display status bar.
*   **ApiServer apiServer**: A mock or actual server handler that synchronizes data across modules when connected to a network (apiServer.handle()).

### State Machine & UI Flow Control
The application's behavior is governed by currentScreen, which can switch between many defined constants (e.g., SCREEN_DASHBOARD, SCREEN_ADD_ITEM, SCREEN_CALENDAR, etc.).

*   **State Transition**: All screen changes must explicitly call a redraw function corresponding to the new state (e.g., moving from Dashboard -> Menu requires calling closeMenu() which in turn calls drawAddItemScreen()).
*   **Input Handling**: The centralized handleTouch(x, y) function serves as the main router for all input events, determining if the touch falls within a button's bounding box and executing the correct action based on the current screen state.

## Usage / Developer Guide

### A. Initialization
1.  Ensure all required libraries (TFT_eSPI, LittleFS, etc.) are correctly installed and configured for the ESP32-S3 board environment.
2.  **First Run**: The build flag #ifdef CLEAR_FLASH_ON_BOOT should be active initially to ensure a clean filesystem mount.

### B. Interaction Flow (Primary User Journeys)

1.  **View Dashboard**: The default landing page showing the inventory items and their remaining shelf life.
    *   Action: Tap on any item card -> Opens Item Context Menu (Add/Edit/Delete).
    *   Pagination: Use < or > buttons at the bottom right to browse pages of inventory.
2.  **Adding an Item**: Navigate via Menu -> Add Item.
    *   Input Name: Opens Keyboard for item name (KB_TARGET_ITEM_NAME).
    *   Select Category: Opens a dedicated category picker screen.
    *   Set Dates/Qty: Use +/- buttons.
3.  **Meal Planning**: Navigate via Menu -> Calendar.
    *   The calendar view allows navigation between months/years and selection of any day.
    *   Selecting a day opens the details view, allowing users to pick a meal (using arrow buttons) or assign one.
4.  **Managing Recipes**: Navigate via Menu -> Meals.
    *   Use + Create New Meal button to enter recipes. Ingredient entry uses a dedicated keyboard flow (KB_TARGET_INGREDIENT) and scrolling logic is applied to the ingredient list view.
5.  **Connectivity Setup**: Tap the Wi-Fi icon in the header -> SCREEN_WIFI_SETTINGS.
    *   Scan: Triggers network scanning, displaying results on a paginated list (SCREEN_WIFI_SCAN_LIST). Selecting a network initiates connection logic and saves credentials.

### C. Key Code Areas for Modification
*   **Screen Constants**: Modify dimensions or fixed coordinates (e.g., BURGER_X, MENU_BTN_H) in the global definitions section.
*   **Input Mapping**: Adjust touch interaction handling in handleTouch() to change button behaviors or screen flow logic.
*   **Domain Logic**: Core business rules (spoiling algorithm, calculation of page indices) are contained within methods on the manager objects (groceryManager, mealsManager).
